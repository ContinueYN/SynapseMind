## 12. M2 交付：让追问由 LLM 生成，状态仍由代码决定

> 本章解决一个问题：**把"问什么"交给模型之后，怎么保证它不越界。**
> 结论先行：M2 只替换"怎么问"，不替换"问什么"，也不动状态机。

### 12.1 边界：M2 只换措辞

M1 的追问是模板句（`GraphProbeComposer` 直接输出解法图里的探针文本）。M2 让模型把同一句话说得更像人——**但探针本身仍由 `ProbePlanner` 从解图里选**。

| 属于 M2 | 不属于 M2 |
|---|---|
| `infrastructure/llm`：客户端、路由、超时、重试、审计 | 解法图怎么来（属 M3 的学科插件） |
| `LLMProbeComposer`：渲染措辞，输出仍是 `ProbePrompt` | 后验怎么算（属领域常量，模型不得参与） |
| 结构化输出校验 + 失败降级 | 检索怎么召回（属 RAG） |
| 开关 `off / shadow / on` | 持久化、鉴权、OCR |

**M2 结束时，部署形态与 M1 完全相同**：仍是内存仓储、无队列、无容器。这是刻意设计的——范围越小，越能证明"受控 LLM"这条主张成立。

### 12.2 三套口径的收敛

仓库里 M2 曾被三种写法描述：里程碑表（最窄，只含 LLM 追问）、根 README 状态行（宽，把 RAG/迁移验证/DB/鉴权都塞进来）、各子目录 README 脚注（更宽，再加 OCR 与复核队列）。本章采用**最窄口径**，理由有二：

1. 它是唯一有 spec 的模块（`specs/dialogue-state.md` 的 8 条硬约束已覆盖追问形态）；
2. 它是唯一有退出条件的模块（"5 轮内区分 2 个假设"）。

其余能力按依赖重新归位：RAG → M3；迁移验证、教师复核、鉴权 → M4；PostgreSQL 是 M3 的第一步。

### 12.3 退出条件：把一句话变成可测

原文只有一句"5 轮内区分 2 个假设"，没有判定口径，因此写不出测试。本章把它对齐到已有代码——`HypothesisSet.decide()` 已经写死：

```python
if confidence >= 0.80 and margin >= 0.25:
    return DiagnosisDecision(kind="diagnose", ...)
```

于是"区分 2 个假设"**就是** `top1 - top2 ≥ 0.25`，与进入 `DIAGNOSE` 的守卫同源，不引入第二套阈值。

**判定方式**：对金标准集逐条回放作答，逐轮记录 `(turn, top1, margin, kind)`。PASS 需同时满足：

1. 存在 `turn ≤ 5` 使 `kind == "diagnose"`；
2. 该轮 `top1` 对应节点与人工标注卡点层一致；
3. JSON 合法率 100%（校验层无重试失败）；
4. 泄漏命中 0。

FAIL 四种：超过 5 轮才诊断；到 6 轮仍 `stop`；top-1 与标注层不符；任一环节触发泄漏降级。

### 12.4 任务与顺序

```text
T1 金标准骨架 ──┬─→ T4 校验+降级 ──┐
                │                    ├─→ T6 shadow 对照 ─→ T7 退出判定
T2 llm 包骨架 ──┴─→ T3 LLM 措辞 ────┘
```

| ID | 任务 | 验收 |
|---|---|---|
| T1 | 金标准骨架（10 条：题目 + 过程 + 标注层 + 逐轮作答） | 可被 pytest 结构化读取 |
| T2 | `infrastructure/llm`：客户端、超时、重试、审计日志 | `off` 模式下全部测试仍绿 |
| T3 | `LLMProbeComposer`：实现 `ProbeComposer`，签名与 `GraphProbeComposer` 完全一致 | mock 客户端返回合法 JSON → `ProbePrompt` 字段齐全 |
| T4 | 校验与降级：Pydantic 校验 → 重试 1 次 → 回退规则实现 | 三类失败（缺字段 / 多问号 / 超时）均回退成功 |
| T6 | shadow：双跑，只记差异不改结果 | 10 条金标准产出差异报告 |
| T7 | 退出判定脚本 | 报告含 `(turn, top1, margin, kind)` 四列 |

工期：T1–T4 + T6–T7 约一人 1.5–2 周，其中标注占一半以上。

### 12.5 不变式

| 约束 | M2 的校验点 |
|---|---|
| 一次一问 | Schema 校验：问号数 = 1，选项 ≤ 4 |
| 前 3 轮无答案 | `ProbePrompt` 类型上不存在 `solution` 字段 |
| **LLM 不决定状态** | 模型只能返回 `ProbePrompt`；`session.advance()` 仍由应用层调用 |
| 低置信不硬判 | `posterior < 0.55` 的逻辑在后验模块，模型不参与 |
| 轮次上限 6 | `max_turns=6`，构造时写入 |
| 动作白名单 | `ProbeAction` 仅允许 `ask` / `hint` / `confirm` |

**分层同样是不变式**：LLM 调用只允许出现在 `infrastructure/llm/`，`domain/` 与 `application/` 不得 import 任何模型 SDK；`lint-imports` 是既有门禁。

答案隔离沿两条硬线：`AnswerStore` 与 `ProbeComposer` 物理分离；LLM 上下文永不包含 `answer_for()` / `solution_for()` 的返回；出口检测装饰器保持最外层。

**规则版是长期基线，不是过渡代码。** `SYNAPSE_LLM_MODE=off` 必须让全部测试与金标准通过——没有基线就没有对照，`shadow` 也无从比对。

### 12.6 验收

```powershell
cd apps/api
pytest                                   # 含金标准回放
ruff check src tests
mypy src
.\.venv\Scripts\lint-imports.exe
```

| 指标 | 阈值 |
|---|---|
| JSON 合法率（含重试） | ≥ 99% |
| 答案泄漏 | = 0 |
| 泄漏误杀率 | ≤ 2% |
| 首问 P95 | < 8s |
| 平均轮数 | 4–6，上限 6 |
| 单次成本 | ≤ ¥0.8 |

> **首问 P95 的测量口径（2026-10-30 晚补）**：门禁脚本量的是 `SessionService.start()`，即服务端那半。真实浏览器端到端另测了一轮：本机 loopback 首屏 4.26–5.63 s、4G 限速（RTT 150 ms）4.64–5.31 s，其中客户端只加 0.06–0.23 s（动态路由取 RSC 的 1 个 RTT）。结论：8 s 的瓶颈是模型输出，不是浏览器；重试样本（schema 重试 ≈7.6 s、claim 修复 ≈5.3–6.3 s）才是需要盯的尾巴。见 [ADR-0004](../../adr/0004-first-question-latency-budget.md) §9 与 `eval/reports/m2-first-question-browser.md`。

评测不使用第三方 prompt 平台：必须能直接调用状态机，用 pytest + JSONL 金标准即可。

### 12.7 灰度与回滚

| 级别 | 行为 | 用途 |
|---|---|---|
| `off` | 全走规则实现 | CI 默认态 |
| `shadow` | 双跑，仅记录差异，返回规则结果 | 上线前零风险对比 |
| `on:10` | 按 `hash(session_id) % 100` 分流 | canary |
| `on` | 全量 | 灰度通过后 |

审计日志字段：`session_id`、`turn`、`model`、`prompt_version`、`latency_ms`、`prompt_tokens`、`completion_tokens`、`retried`、`fallback_reason`、`schema_ok`。

回滚是**一次环境变量变更**，无需发布——这是"不改状态机、不改路由、不加页面"的直接回报。

### 12.8 风险

| 风险 | 表现 | 缓解 |
|---|---|---|
| **状态机被模型架空** | 一旦让模型决定"下一步问什么"，8 条硬约束全部失效，产品退回聊天机器人 | 模型只改措辞；选哪个探针仍由 planner 决定 |
| 0 泄漏与提示有效性冲突 | 闸门太严 → 追问无信息量 → 退出条件达不成 | 误杀率 ≤2% 与泄漏 0 同等硬 |
| 首问预算被重试顶穿 | 重试 + 双跑把 P95 拉过 8s | 单次超时上限、`shadow` 不阻塞返回、失败即降级 |
| 非确定性导致金标准抖动 | 同一 case 两次结果不同，CI 偶发红 | `temperature=0`、固定模型版本、记录 `prompt_version` |

开工前需定两件事：**模型与供应商**（可直接阻塞 T2）、**金标准规模**（10 / 100 / 200 三个口径并存，决定 T1 是半天还是两周）。

> **2026-10-29 已定**：DeepSeek `deepseek-chat`（OpenAI 兼容抽象，换供应商只改 `base_url` + `model`）；金标准 10 条（`eval/golden/golden-v0.1.jsonl`，字段按 100 条口径建）。取舍与改选条件见 [ADR-0002](../../adr/0002-llm-provider-and-golden-scale.md)。
