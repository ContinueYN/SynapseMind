## 13. 学科插件与可扩展架构：从一道题到任意题

> 目标是任意题、全学科。卡住的从来不是状态机，是**解法图需要人工标**。
> 这一章回答：怎么在不改对话内核的前提下，让解法图由模型生成、且结论仍可证伪。

### 13.1 契约早已为全学科写好

检查 `specs/` 会发现一件有利的事：产品契约本来就是按"通用认知诊断"设计的，只有一处需要改。

| 契约要素 | 现状 | 是否支持全学科 |
|---|---|---|
| `node.type` | `READ` / `CONCEPT` / `CONDITION` / `STRATEGY` / `TRANSFORM` / `COMPUTE` / `CHECK` | ✅ **认知动作，不是数学动作**——读题、概念提取、条件转译、策略选择、变形、计算、校验，换成阅读题依然成立 |
| `node.demand` | V / Gf / Gv / WM / Gs / LTS / M 七维 | ✅ CHC 七维本就跨学科 |
| `edges` | `[from, to]` 依赖对 | ✅ 学科无关 |
| `probes[].targets` | 指向节点 | ✅ 学科无关 |
| `problem.subject` | 枚举仅 `["math"]` | ❌ **唯一的契约级改动** |
| `problem.grade` | 枚举仅 `["high_school"]` | ❌ 同上 |

因此"全学科"不是推翻重来，而是**兑现一张已经写好的契约**。

### 13.2 实现层的五处硬编码

| 位置 | 现在 | 全学科要求 |
|---|---|---|
| `infrastructure/seed.py` | 一道种子题 + 4 个探针 + 标准答案 | 任意题 |
| `application/factory.py` 的 `_ALIGNMENT_SUPPORT` | 写死 `n1→H_L1` 等映射 | 每张图自己给出节点与假设的支撑关系 |
| `domain/problem/alignment.py` 的 `_NODE_RULES` | 6 条中文关键字规则 | 语义对齐（模型生成 + 校验） |
| `domain/diagnosis/hypotheses.py` 的 `EVIDENCE` | 人工写的 log-odds 表 | 按图生成证据模型 |
| `infrastructure/in_memory.py` 的 `find_for` | 关键字命中，否则 422 | 识别任意题 |

五处合起来就是一句话：**图必须人工标，所以只能做一道题。** 100 道题可以标，全学科不可能。

### 13.3 可验证性三档

卡点定位的可信度取决于该学科能否被自动验证。不分档，"有证据的卡点"会在不可验证的学科里退化成修辞。

| 档位 | 学科 | 可用验证手段 | 承诺边界 |
|---|---|---|---|
| **STRONG** | 数学 | 符号等价、数值代入、反例构造 | 定位到 L2（条件转译/参数分类），**附可证伪的反例** |
| **PARTIAL** | 物理、化学 | 量纲/单位、代数结构、数值回代 | 定位到步骤级；概念层只给"候选卡点 + 置信度" |
| **NONE** | 语文、英语、历史 | 无客观真值 | **只做结构提示**，不做卡点归因，不生成卡点卡 |

物理的 S6 接入按 PARTIAL 承诺：生成图、探针、证据与卡点卡都能跑；`verify()` 读取可选的 `StudentStep.data`，在**结构化步骤**上做量纲一致性与数值回代。没有 `equation`/`expression` 或 `units` 时返回 `unknown`；有单位但缺 `values` 时只做量纲检查并在 detail 明说“未做数值回代”。它绝不从自然语言里猜单位——**能跑通链路不等于能验证每一步**，报告里不能把 `unknown` 写成“已核对”。

当前卡点卡之所以站得住，是因为数学能验：`ln x − ax ≤ 0` 要求对所有 `x>0` 成立，`a≤0` 这一支必须单独检查——代入 `a=−1` 看到 `f(x)→+∞`，就能证明它不满足、必须排除；学生漏的是这一步检查，不是答案里的一支。换成作文，"你卡在条件转译"无法证伪——同一句话在数学上是证据，在语文上是修辞。

分档不是降低野心，是**让野心可交付**。状态机骨架完全共用，不同的只是插件的验证器与对外承诺。

### 13.4 插件接口

放在应用层端口，实现放基础设施层，与既有 Protocol 同风格：

```python
class VerifiabilityLevel(StrEnum):
    STRONG = "strong"
    PARTIAL = "partial"
    NONE = "none"

class SubjectPlugin(Protocol):
    subject: str
    level: VerifiabilityLevel

    def identify(self, text: str) -> ProblemRef | None: ...
    def build_graph(self, problem: Problem | ProblemDraft) -> SolutionGraph: ...
    def aligner_for(self, problem: Problem) -> StepAligner: ...
    def probes_for(self, node: SolutionNode) -> tuple[Probe, ...]: ...
    def evidence_model(self, graph: SolutionGraph) -> EvidenceModel: ...
    def verify(self, step: StudentStep) -> Verdict: ...
```

插件还可以提供可选的 `hypothesis_labels`（`假设 id → 该学科的文案`）。它不是评分接口：假设 id、先验、log-odds 和诊断门槛完全共用，只有卡面措辞换成学科词表。这样物理卡不会说「恒成立与最值」。

`aligner_for()` 是 S8 新增的**对齐策略端口**：插件决定这道题用哪种 `StepAligner`，`SessionFactory` 不再自己按学科分支。数学在标注题/生成题之间切规则与类型线索，物理保持两态匹配，语文用分句级匹配。它只改变「怎么判断这一步有没有被写到」，不改变状态机、探针门槛或卡点卡的生成条件。

**结构化步骤载荷（S6 后续）。** `StudentStep` 增加一个通用的可选 `data: Mapping[str, object] | None`，键由学科自己约定，状态机与数学插件都不读它。物理约定如下：

| 键 | 含义 |
|---|---|
| `equation` | 恰好一个 `=` 的标量方程，如 `F*cos(theta) - mu*N = m*a`；只允许数字、已声明符号、`+ - * / **`、括号、`pi` 与 `sin/cos/tan/asin/acos/atan/sqrt/exp/log/ln/abs`，不接受隐式乘法 |
| `expression` | 没有 `=` 时写的量或表达式；此时必须配 `unit` |
| `unit` | 声明结果单位；`expression` 必填，`equation` 可选（检查方程右侧） |
| `units` | `符号 → 单位表达式`，方程里每个符号都要有；无量纲写空字符串（如 `mu`）。单位用 7 个 SI 基本量加 `N/J/W/Pa/C/V/ohm/Hz/F/T` 等常用导出单位 |
| `values` | `符号 → 数值`，按该符号声明的单位给出；验证器先换成 SI，再只在**所有自由符号都有值**时做数值回代 |
| `expected` | 可选的学生结果 `{"value": 数值, "unit": 单位}`；与方程右侧（无方程时与 `expression`）比较 |
| `tolerance` | 可选数字，或 `{"relative": ..., "absolute": ...}`；默认相对 `1e-6`、绝对 `1e-9` |

`verify()` 的 `pass` 只表示“实际跑过的检查没有发现不一致”，`detail` 必须写清是只做了量纲还是也做了数值回代；`fail` 要带两侧量纲或具体数值差；`unknown` 要说明缺哪个字段/符号/单位。物理不新增 `claim`，也不把数学 SymPy 验证器套到物理上。

三条设计约束：

1. **`verify()` 允许返回 unknown**——这是 NONE 档的诚实出口，不是缺陷；上层据 `level` 决定是否允许 `diagnose`。
2. **状态机不认识插件**——`DialogueSession`、转移表、应用服务一行不改；插件只在进入 `ALIGN` 之前提供内容。
3. **生成的图必须过 schema 校验 + 结构修复**——`solution-graph.schema.json` 已限制节点 3–20 个、类型枚举、探针 ≤10，天然是生成物的护栏。

### 13.5 生成流水线与失败路径

```text
交题 → identify() → build_graph() → schema 校验 → 关键节点抽查验证
     → probes_for() → evidence_model() → 进入现有状态机（ALIGN 起）
```

失败必须显式，不允许静默降级：

| 失败 | 处理 |
|---|---|
| 图不合法，修复 1 次仍失败 | 返回"当前版本无法拆解这道题"，**不生成卡点卡** |
| 节点 < 3 或依赖无法建立 | 同上（对应风险"约三成题目无法建图"） |
| `level == NONE` | 只出结构提示，不进入 `PROBE` |
| STRONG 档验证全部 unknown | 降级为 PARTIAL 承诺，卡点卡标注"未验证" |

### 13.6 稳定性与成本

概率生成的最大敌人是**同一道题两次生成不同的图**，会让退出条件测试不可重复。对策：`temperature=0` + 固定模型版本 + 固定 prompt 版本；生成结果按题目文本哈希缓存（`(subject, graph_id)` 已是既有索引形态）；图结构指纹写入审计日志，便于回归比对。

成本上，每题一次建图 + 探针生成，与"单次 ≤ ¥0.8"的预算需要重新核算——这是 M2 之后必须重定的一笔账。

> 2026-10-29 S5 第一阶段：证据表从全局常量改为会话数据。`HypothesisSet.from_alignment(..., evidence=...)` 接受插件给出的权重，`SessionFactory` 在创建会话时调用 `SubjectPlugin.evidence_model()`；`EVIDENCE` 只作为没有插件时的默认值。种子题补齐 `p_union` 的权重（此前该探针答了也不更新后验，白耗一轮），并加契约测试保证**每个探针的每个选项都有权重、且只指向已知假设**。10 条 golden 仍为 10/10、平均 2.40 轮，不低于基线。
>
> 2026-10-29 S5 第二阶段（生成图的证据权重）：生成图新增可选的 `probe.evidence`（`选项 → 假设 → log-odds`），生成 prompt 升级为 `graph-v2`。结构规则要求每个选项都有权重、权重键必须在该探针 `targets` 内、每个 target 至少被一个选项使用、权重有正有负（否则区分不了假设）、落在 −1~1（越界机械钳制并记录）；`MathPlugin.evidence_model()` 对生成图读取图内权重，只有已标注的种子图才回退 `EVIDENCE`，未知图返回空表而不是借用种子题的权重。真实 20 题重跑：结构 18/20（90%；`P_DERIV_007`/`P_GEOM_001` 两次生成都没有探针），**68/68 个探针、204/204 个选项都有权重，68/68 有正负对比**；4 次重试，2 次重试后通过、2 次因 `no_probes` 失败；p50 3.91s / p95 5.04s（prompt 变长使 p95 从 4.54s 上升）。**仍未解决**：`P_DERIV_003` 依旧漏掉 `a=0`——证据权重只保证「答了会更新后验」，不保证「图的数学结论正确」；后者仍要 SymPy 验证器与反例，且验证器需要图先给出可形式化的断言，属 S5 下一阶段。
>
> 2026-10-29 S5 第三阶段（答案可被反例打脸）：S4 抽查暴露的「`P_DERIV_003` 漏 `a=0`」不能靠改措辞修——纯文本节点只能检查「显式写出来的分支」。这一阶段先做形式化，再接验证：
>
> - **字段**：图顶层加**可选** `claim`（`specs/solution-graph.schema.json` 的 `$defs/claim`）。语义是一句可证伪的陈述：`∀x∈D: f(x,a) rel 0 ⇔ a ∈ answer`，其中 `rel ∈ {<=,>=,<,>}`、`answer` 由若干闭/开区间组成（`null` 表示无穷，无穷一端强制开）。v1 只有 `parameter_range` 一种 `kind`；求一个值、解集、证明题没有 claim，验证结果记 `unknown`，不算失败。
> - **验证器**（`infrastructure/verification/`）：SymPy 解析约束，x 取「线性网格 + 12 个数量级 + 边界加密」，参数在区间内/外分别取样（含端点本身、端点外 ±δ、区间空隙），在最紧处做黄金分割细化，返回 `pass|fail|unknown`。两个方向都查：区间内不满足 → 答案偏宽；区间外满足 → 答案偏窄。`fail` 必带反例（`a=…, x=…, 表达式=…`），`unknown` 是读不懂、无定义或落在 1e-9 容差带。**它是证伪器，不是证明器**：`pass` 只表示在采样里没找到反例。
> - **接入**：建图流程变成「生成 → 机械修复 → 结构规则 → schema → 验证 → 一次带反例的重试」。prompt 升到 `graph-v3`（第 11 条写死 claim 形状、端点代回检验、`e`/`E`、`log_2`；第 12 条写死「探针必须在节点内部」——实测模型会把探针扁平化到顶层，那种图没有归属信息，判 `probes_top_level` 让重试改）。
> - **两次降级的边界**：claim 形状不支持（`kind`/`relation` 不在 v1、`parameter` 与 `variable` 同字母）→ 直接丢弃并记 `claim_dropped_unsupported`，不浪费重试；被反例推翻且重试一次仍错 → 丢弃 claim 并记 `claim_dropped_refuted`，**图保留**、反例留在 `GraphBuildResult.verification`。理由：`P_GEO_001` 这类题图是对的，只是把「有两个交点」形式化成了错的约束；整题报废等于用元数据的错误惩罚解法，但答案必须失去「已核对」身份，不能让下游把被推翻的区间当结论。
> - **实测（20 道未见题，真实 key，`graph-v3` 连跑四轮）**：建图稳定 **20/20**；最后一轮 23 次调用、3 次重试，p50 4.05s / p95 5.51s。20 题里只有 `P_DERIV_003` 属于 v1 能形式化的形状，四轮都给出同一个错的 `a∈(-∞,e]`：`a=-24.46` 在答案区间内，`x=-6.8e12` 时表达式 `-1.67e14 < 0`；带反例重试一次，模型仍写同一区间，于是丢弃 claim、保留图。模型偶尔还会把存在性条件（`P_DERIV_004` 两个零点、`P_GEO_001` 两个交点）写成 `relation:"="` 的 claim，四轮里出现 0–3 次，按形状不支持丢弃。报告：`eval/reports/m2.5-s5-verification.md`，内含**变形自检**（把种子 claim 改成全实轴、端点放宽 1，验证器 2/2 拒绝）与**正向对照**（同一题 `[0,e]` → `pass`、`(-∞,e]` → `fail` 并给出具体反例）。
> - **仍未解决**：① claim 覆盖率低——四轮里每次只有 `P_DERIV_003` 一题给出 claim，且都没修对；「端点必须代回检验」的 prompt 约束挡不住 `a=0` 这类边界，回灌反例也没有第二次修正的机会。② 同一道题两次生成仍不可重复（S4 已记录），验证结论只对该次图有效，不能当稳定基线。③ 验证器目前只支持「单参数 + 单变量 + 恒成立」形状，多参数或解集型答案要等 `kind` 扩展。
>
> 2026-10-30 S5 第四阶段（把生成图接进 ALIGN/PROBE）：前三阶段只把图「生成出来」，主链路仍然 422，因为对齐与卡点卡都写死了种子节点。这一阶段把两处写死拆掉，**入口不变 422 的语义也不变**——只是「服务不了的题」从「非种子题」缩小为「当前环境建不出图的题」：
>
> - **通用对齐**（`domain/problem/alignment.py`）：`TypeCueAligner` 按节点类型查「有没有被提到」，证据只有两类——该类型的线索词是否出现、过程里是否出现过任何一个式子（`COMPUTE`/`TRANSFORM` 才算落实）；外加两条兜底：同一个字母出现 `a≤0`/`a>0` 两个方向即视为分类讨论，正文与节点文本共享 3-gram ≥0.5 视为提到。它是**存在性检查，不是正确性检查**：能发现「这一步没写」，不能发现「这一步写错」。`CompositeAligner` 按 `annotated_ids` 分发，两个策略互不知道对方存在，规则版仍是标注库的基线（红线 3）。
> - **先验按类型给**（`domain/diagnosis/hypotheses.py`）：`NODE_TYPE_LAYER` 把 `READ`/`CONCEPT` 映射到 L1、`CONDITION`/`STRATEGY`/`TRANSFORM`/`CHECK` 到 L2、`COMPUTE` 到 L4，`FOCUS_PRIORS` 给出对应先验；`from_alignment(..., focus=...)` 有 `focus` 时按类型，没有时仍走种子的节点档案——标注库的结果逐字节不变（10 条 golden 仍 10/10）。
> - **通用卡点卡**（`application/card_builder.py`）：生成图没有 `_ONE_LINE`、没有种子任务 id，所以卡面改成「引用推动后验的那次作答」——「你在「{节点}」这一步选了「{选项}」，这道题更像是「{标签}」层面的问题。」；没有探针证据时只写「过程里没有出现「{节点}」这一步」。`concept_id`/`item_id` 用 `node:{id}`/`verify:{problem_id}`，前端只读 `label`/`next_action.type`/`duration_min`/`due_hours`，自由取值安全。
> - **接线**（`application/problem_resolver.py` + `api/deps.py`）：提交的题干先查标注库（严格包含，不变），未命中就调 `SubjectPlugin.build_graph()` 现场建图，用 `P_GEN_<stem 指纹>` 作 id 存进同一次进程的仓储（同一题不会重复生成），标记 `annotated=False`。没有建图器（`SYNAPSE_LLM_MODE=off`、缺 key、`shadow`）或建图失败 → 仍是 422，且理由说得出口。
> - **实测（20 道未见题，真实 key，`aligned` 作答策略）**：建会话 **20/20**（含现场建图），出卡 **7/20**，**卡点节点 7/7 都属于该图**；建会话 p50 5.4s / p95 35.9s（两次生成重试把尾巴拉长）。报告：`eval/reports/m2.5-s5-session.md`。`aligned` 策略是**构造出来的学生**（按「与对齐结论一致」作答），所以出卡率描述的是「链路在理想作答下能走到哪」，不是诊断准确率。
> - **出卡率为什么只有 7/20**：门槛仍是 M2 的「后验 ≥0.80 且领先 ≥0.25」，而生成图每题只给 3–7 个探针、权重 max|w|=0.60（85 个探针 510 条权重里 |w|≥0.8 的 **0 条**），targets 又分散在 L1/L2、L1/L4、L4/L2 等不同假设对上——后验在 6 轮里被来回推动，攒不出 0.25 的领先。所以这张表的读法是：**接线成功看「建会话 20/20」与「节点 7/7 在图内」**；出卡率衡量的是探针/权重校准，要靠 S5 ③ 调 prompt（更强的权重、更集中的 targets）或给未见题单独标定门槛解决，不能靠悄悄调低阈值。
> - **仍未解决**：① 生成题没有存储答案，泄漏守卫退化为通用短语检查（`guards.py` 里写明了降级），n-gram 规则在这一支上不生效；② 存在性对齐意味着卡面不能断言「这一步错了」，无探针证据时只能报「没出现」；③ 首问预算 8s 现在包含一次建图（p50 4–5s），且生成重试会把 P95 拉到 30s 以上，`on:10` 灰度时要单独看这一支的 P95；④ 同一题干两次提交会命中同一 `P_GEN_*`（进程内缓存），但重启进程后会重新生成——图不稳定（S4 已记录）意味着「同一题两次诊断可能落在不同节点上」。

> 2026-10-30 S5 ③/④（探针/证据权重校准；claim 负参数分支仍未解决）：
>
> - **prompt 升到 `graph-v6`**：① 每个探针至少有一个权重达到 ±0.8~1.0，同一个假设在不同选项上的权重差至少 1.0；整张图的探针必须覆盖 H_L1/H_L2/H_L4 三个假设。② claim 的端点检查加三条硬约束：parameter=0、parameter<0、variable→±∞ 都要单独过一遍，负参数分支不能用「a>0 时的最值结论」覆盖；对 a<0 的分支要求代一个具体负数与足够小的 x 做数值检查。③ 反例反馈里写明「若反例的 parameter<0，除非能证明该段整体成立，否则删除所有负参数取值」——只靠原样回灌，模型会重复同一个错区间。
> - **一次不计入的试跑**：中间曾在 prompt 里写 `e^x−a x` 作为负参数例子，`P_DERIV_003` 一次就改对；那等于把评测题写进 prompt，不是能力提升。删掉具体函数、只保留通用规则后重跑，模型仍写 `(-∞,e]`，所以这个「通过」不计入 ④ 的结论。
> - **兜底校准**（`domain/problem/graph_structure.py`）：`review(..., calibrate_evidence=True)` 只在生成图、且全图最大 |w|<0.90 时，按**全图统一系数**放大到 0.90；只放大不缩小，不改符号、不改探针之间的相对强弱，并记 `evidence_calibrated`。手写种子图不走这条分支。决策与备选（降门槛、逐探针归一化）见 ADR-0003。
> - **实测（20 道未见题，真实 key，`graph-v6`，`aligned` 策略）**：建会话 **20/20**，出卡 **20/20（100%）**（上一轮 7/20），卡点节点 **20/20 属于该图**；125 个探针（每题 5–7 个，均值 6.2）、750 条权重，max|w|=0.90，|w|≥0.8 的有 350 条；建会话 p50 6.4s / p95 9.3s，总探针轮数 62。报告：`eval/reports/m2.5-s5-session.md`。卡点层分布 L1 19 / L2 1——`aligned` 策略在会话开始时把目标层固定为对齐缺口所在层，这不是「这批题都该诊断成 L1」。
> - **④ 的结果**：`graph-v6` 下 `P_DERIV_003` 第一次仍写 `(-∞,e]`，反例 `a=-24.46, x=-6.8e12` 把负参数段推翻；带反例重试一次后模型仍保留负参数段，于是按设计**丢弃 claim、保留图**。20 题里 claim 被接受 **0**、被推翻 **1**、其余 19 题按形状不输出 claim。结论：当前模型能写出 claim 的形状，但推不对负参数分支；④ 的下一步不是继续加 prompt，而是换更强模型、或在验证器之外增加「只证伪、不合成答案」的更强反例搜索。
> - **仍未解决**：① `aligned` 策略是构造学生，20/20 是「理想作答下链路能走到卡」的上限，不是诊断准确率；② 同一题重生成仍可能给出不同图，验证结论只对该次图有效；③ 0.90 是证据强度的校准，不是数学正确性的证明，claim 之外的步骤仍只能做存在性对齐；④ claim 覆盖率仍是 1/20（题型决定），且唯一那题仍被推翻——验证器能拦住错误答案，但不能替模型把答案改对。

> - **契约 v0.2**（`specs/structure-hint.schema.json`）：`version` 从 `0.1` 升 `0.2`，`steps[].status` 增加 `partial`，描述明确三者都只表示「有没有被写到 / 是否只写到一部分」，不表示对错；`focus_node_id` 改为「第一个没有完全写到的节点」。`hint_builder.py` 把 `partial` 映射为「写到了一部分」，focus 取第一个非 `covered`，`next_step` 用「先把…补全」；`StructureHint.version`/`HintOut.version` 同步，前端计数改成「有写到的步数（含部分）」，步骤标签加「写到了一部分」。
> - **实测（6 道语文题 × 3 段过程 = 18 次建会话，真实 key，`graph-v6-chinese`）**：建会话 **18/18**、结构提示 **18/18**、schema v0.2 合规 **18/18**、服务返回与直接调用 `ClauseCueAligner` 一致 **18/18**、出卡 **0/18**、出探针 **0/18**、`CLOSED` **18/18**。**同一张图**上对比旧/新对齐器：旧 full 的 covered 均值 1.7；新 full 的 covered 均值 1.7、partial 均值 2.3、加权均值 2.8（partial 记 0.5）；`full ≥ partial`（加权）6/6、`full 新 ≥ 旧` 6/6、full 有提升 6/6、blank 全 `missing` 6/6。报告：`eval/reports/m2.5-s8-clause-alignment.md`。
> - **边界**：分句匹配仍是字面重合，同义改写、没有共同字词的过程仍会判 `missing`；`partial` 只表示「节点里至少一个小句被写到」，不判断这一半对不对，也不改变 NONE 档不出卡/不出探针的承诺；阈值（小句 ≥4 字、公共段 ≥4 字、75%/15%）由固定用例锁住，不按评测结果回调。数学/物理没有 opt-in 分句匹配，S5/S6 的卡点节点与数字不变；`domain/dialogue/` 一行未改。
> - **仍未解决**：① 没有语文标注题集与真实学生作答，18/18 是「接线 + 对齐策略」的验收，不是诊断准确率；② 分句匹配不是语义匹配，换一种说法仍会漏；③ `partial` 的 75%/15% 是启发式阈值，只在 6 道题上验证，扩题后要重新看误报；④ 语文图仍不稳定，同一题重启后重新生成可能给出不同步骤。

### 13.8 结论

**状态机保证对话可控，学科插件保证可扩展，验证器保证诊断可证伪。**

三句话对应代码里三个可指认的位置。全学科的难点不在模型，而在**为每个学科找到"能打脸"的验证手段**——找不到的学科，就不该承诺"找到你卡住的那一步"。
