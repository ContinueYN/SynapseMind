## 11. 设计过程：5 个“无共享记忆”的子 Agent

> 这一章不是产品功能，而是说明这份方案是怎么被“吵”出来的。
> 5 个子 Agent 共享同一份事实包，但彼此看不到对方的输出；主 Agent 只做冲突裁决与整合。

### 11.1 为什么要无共享记忆

如果让 5 个 Agent 在同一个群里聊，会出现：

- 锚定：第一个说“做 12 分钟测评”的人，把后面的人带偏；
- 迎合：后面的 Agent 倾向同意前面的结论；
- 责任稀释：错了不知道是谁的假设。

无共享记忆 + 独立产出，强制每个角色从自己的专业视角把话说完，再由主 Agent 做“对抗性整合”。

### 11.2 五个角色与提示词

**A 需求/对话设计师**

```text
你是学习产品的对话设计师。用户需求：学生发来一道不会/做错的题和自己的答案，
系统要通过追问定位他具体不会的点。请只输出：
1) 3 个真实用户场景；2) 一次 8 分钟对话的逐轮脚本；3) 5 条对话硬规则。
约束：不要设计题库/课程/测评；不要给完整解答；一次只问一个问题。
```

**B 认知科学家/诊断引擎**

```text
你是认知科学与教育测量背景的算法设计师。请把“学生不会”拆成可观察、可追问、
可更新的假设空间，并给出：1) 卡点分类；2) 每类的信号与探针；3) 置信度更新与停止条件。
约束：不输出 IQ/诊断标签；必须能落到一道高中导数题。
```

**C 后端/AI 架构师**

```text
你是 Java/Spring Cloud + RAG 架构师。3 人 8 周，要支持“单题诊断对话”。
请给出：1) 4 个部署单元与 7 个服务边界；2) 核心表；3) 一次对话的调用链；
4) 缓存/可观测性/降级；5) 如何体现 skill.txt 的 11 项能力。
约束：不要一上来 9 个微服务；不要为了用中间件而用。
```

**D 教研/内容负责人**

```text
你是高中数学教研负责人。请给出：1) 100 道题如何选；2) 30 道深标怎么标；
3) 解法图节点与探针模板；4) 双人标注一致率怎么算；5) 哪些题必须放弃。
约束：不追求题量；必须能在一个月内标完 30 道。
```

**E 红队/苛刻评审**

```text
你是投资人的技术顾问，任务是杀死这个项目。请攻击：
1) 诊断是否伪科学；2) 任意题覆盖；3) 答案泄漏；4) 用户是否愿意被追问；
5) 3 人 8 周是否可能；6) 成本与合规。
输出：按“致命/严重/可接受”分级，每条给一个验证实验。
```

### 11.3 主 Agent 裁决的 6 个冲突

| # | 冲突 | A/B 方 | 裁决 | 理由 |
|---|---|---|---|---|
| 1 | 做 12 分钟测评，还是单题诊断 | A 想测评；B 想单题 | **单题诊断** | 用户当下带来的是一道题；测评是另一个产品 |
| 2 | 对外给七维画像，还是 L0–L6 卡点 | B 想七维；A 想人话 | **L0–L6 主输出，七维只做探针镜头** | 用户要“哪一步”，不要“能力分数” |
| 3 | 4 个 Agent 还是 7 个 | C 想 7 个；A 想 4 个 | **MVP 4 个，目标 7 个** | 3 人 8 周，先跑通状态机 |
| 4 | 4 个部署单元还是 9 个服务 | C 想 9 个；D 想快 | **4 单元，7 服务边界** | 边界先立，进程后拆 |
| 5 | 学习模式要不要给答案 | A 想锁；E 说用户会跑 | **锁到诊断后，但给“直接看答案”出口** | 不道德绑架；出口退出学习模式 |
| 6 | 1000 用户还是 40–60 beta | D 想规模；E 想验证 | **40–60 beta** | 先证明一致率，再谈增长 |

### 11.4 红队改变了什么

红队 E 的输出最短，但改变了三件事：

1. **删掉“12 分钟测评”**：它会把单题诊断做成另一个产品，且需要常模，8 周做不出来。
2. **把“七维画像”降级为内部探针**：对外只说卡点，避免“智商测试”联想。
3. **加 kill criteria**：如果 50 次诊断一致率 <60%，停止扩张，回到 10 道题。

### 11.5 这套方法怎么复用到别的项目

- 事实包只给一次，避免每个 Agent 重复读长文；
- 每个 Agent 的输出必须带“约束/取舍/验证实验”，不只给结论；
- 主 Agent 不做“平均”，做“冲突裁决”，并记录理由；
- 红队必须独立，且有权否定前四个；
- 最后用一份“诚实清单”收尾，写明没做什么。

### 11.6 与运行时多 Agent 的区别

| | 设计时子 Agent | 运行时 Agent |
|---|---|---|
| 目标 | 产出方案 | 完成一次诊断 |
| 记忆 | 无共享 | 共享 session state |
| 编排 | 主 Agent 裁决 | 确定性状态机 |
| 输出 | 文档/表格 | JSON/追问/卡点卡 |
| 失败 | 重跑/人工整合 | 降级/模板/人工复核 |

**不要把“设计时多 Agent”当成“产品多 Agent”。** 前者是方法，后者是架构；两者都要，但不能混为一谈。
