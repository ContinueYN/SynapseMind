## 1. 需求：用户带来的不是“题”，是“卡住”

### 1.1 三个真实场景

**场景 A：完全不会。**

一个高一学生拍来一道题：

> 已知函数 `f(x)=x³-3x+1`，讨论方程 `f(x)=0` 的实根个数。

他只打了一句：“完全不会。”

传统产品的反应是：识别题目 → 给完整解答。学生看完，“哦”一声，下次遇到同型题还是不会。因为他不会的不是“这道题的答案”，而是“怎么想到用零点定理 + 单调性 + 端点值”。

**场景 B：做错了，但不知道错在哪。**

一个高二学生发来题目和自己的答案：

> 题目：`f(x)=ln x - a x`，`a∈R`，若 `f(x)≤0` 对任意 `x>0` 恒成立，求 `a` 的取值范围。
>
> 学生：`f'(x)=1/x-a`，令 `f'(x)=0` 得 `x=1/a`，最大值 `ln(1/a)-1≤0`，所以 `a≥1/e`。

答案是对的，过程漏了 `a≤0`。如果系统只说“你漏了 a≤0”，学生记住的是“这题要分类”，下次换一个参数，仍然不知道“什么时候需要先检查驻点存在”。

**场景 C：答案对，但心里没底。**

学生说：“我选 C，但我是排除法猜的。”

这时最危险：分数掩盖了理解的空洞。系统要问的不是“为什么选 C”，而是“你能构造一个反例，说明 B 为什么不对吗？”

### 1.2 现有产品断在哪

| 产品形态 | 它解决了什么 | 它没解决什么 |
|---|---|---|
| 搜题/题库 | 快速拿到答案 | 不知道“我为什么没想到” |
| AI 家教 | 把解答讲清楚 | 讲的是“题”的逻辑，不是“你”的断点 |
| 错题本 | 把错题存下来 | 只记录“错了”，不记录“错在哪个认知动作” |
| 知识点标签 | 告诉我“函数单调性薄弱” | 太粗：同一个标签下，可能是读题、概念、策略、计算、校验五种病 |
| 自适应刷题 | 根据正确率推题 | 正确率是结果，不是过程；蒙对和真会无法区分 |

**空白点**：从“这道题我错了”到“我具体缺哪个认知动作”之间，缺一层**可解释的诊断**。

### 1.3 项目的原子单位

不是“学生”，也不是“题目”，而是：

> **一次作答 = 一个学生 × 一道题 × 一条过程。**

同一道题，三个学生可能卡在三处：

- 学生 A：读不懂“对任意 x>0 恒成立” → L0 语义。
- 学生 B：不知道 `f'(x)=0` 只是必要条件，还要判断极大/极小 → L1 概念。
- 学生 C：知道要分类，但一分类就漏 `a=0` → L2 条件转译 + L4 执行。

如果系统只给“知识点：导数应用”，这三个人会拿到同一份练习。这就是无效刷题的根源。

### 1.4 我们的承诺

**8 分钟内，给你一个可命名的卡点，而不是一整道题的解答。**

具体承诺：

1. 第一轮追问在 8 秒内出现；
2. 最多 6 轮，必须给出阶段性结论；
3. 结论必须带证据（引用你刚才的原话/步骤）；
4. 必须给出“排除了什么”，防止把多因一果简单化；
5. 必须给一个 3 分钟能做完的下一步；
6. 学习模式下，不直接给最终答案。

### 1.5 边界

| 维度 | MVP 边界 | 原因 |
|---|---|---|
| 学科 | 高中数学“函数与导数” | 解法图相对可控；SymPy 可验证 |
| 题型 | 求参数范围、单调性、极值、零点个数、恒成立 | 覆盖高频且可分步 |
| 输入 | 文本/拍照；答案可手写/文本 | OCR 是最大工程风险，先做 Mathpix 类兜底 |
| 输出 | 卡点卡 + 3 分钟微干预 + 1 道迁移题 | 不承诺完整课程 |
| 用户 | 高一至高三 | 不含小学/大学 |
| 不做 | 医学诊断、智商分数、排名、提分承诺 | 伦理与合规红线 |

### 1.6 为什么现在能做

三件事同时成熟：

1. **多模态输入**：拍照 + LaTeX OCR 已经可用，学生不需要敲公式。
2. **结构化输出**：LLM 能稳定输出 JSON，把“追问”变成可测试的状态机，而不是聊天。
3. **小模型成本下降**：一次诊断 4–6 轮，每轮 1–2k token，成本可以压到 ¥0.8 以内。

但真正的壁垒不是模型，是：

> **把“老师会怎么追问”拆成可复用的探针库，并且让每一道题都有可对齐的解法图。**

这部分是脏活，也是本项目最值得讲的地方。
