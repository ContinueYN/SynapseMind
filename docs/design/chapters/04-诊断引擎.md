## 4. 诊断引擎：从“答案”到“卡点”

### 4.1 题目不是一段文本，是一张解法图

系统对每道题生成一张 **Solution Graph**。节点不是“解题步骤”的流水账，而是“认知动作”：

| 节点类型 | 含义 | 例子 |
|---|---|---|
| `READ` | 读懂题意、符号、量词 | “对任意 x>0 恒成立” |
| `CONCEPT` | 调用定义/定理/公式 | 导数与单调性的关系 |
| `CONDITION` | 把文字条件转成式子/图形/分类 | `a>0` 时才有正驻点 |
| `STRATEGY` | 选择整体路径 | 先分类，再求最值 |
| `TRANSFORM` | 等价变形 | `ln(1/a)≤1` → `a≥1/e` |
| `COMPUTE` | 计算/代数 | 求导、解不等式 |
| `CHECK` | 校验、边界、反例 | 检查 `a=0`、`a<0` |

每个节点带四类元数据：

```json
{
  "id": "n4",
  "type": "CONDITION",
  "text": "确认 a>0 时，驻点 x=1/a 才落在定义域 x>0",
  "concept": "parameter_classification",
  "demand": {"V": 3, "Gf": 4, "WM": 3, "Gs": 1, "LTS": 2, "M": 4},
  "prerequisites": ["n2"],
  "common_errors": ["E_NOCASE", "E_DOMAIN"],
  "probe_templates": ["P_CASE_COUNTEREXAMPLE", "P_DOMAIN_CHECK"]
}
```

**关键**：`demand` 不是“题目难度”，而是“这一步对哪种认知资源的需求”。同一道题，对不同学生，卡在不同节点。

### 4.2 学生作答不是“对/错”，是一条可对齐的步骤链

系统把用户提交的答案拆成步骤：

```json
{
  "attempt_id": "A_1024",
  "steps": [
    {"id": "s1", "text": "f'(x)=1/x-a", "maps_to": "n3", "status": "ok"},
    {"id": "s2", "text": "令 f'(x)=0，得 x=1/a", "maps_to": "n4", "status": "partial",
     "evidence": "未说明 a>0；a=0 时除法无意义"},
    {"id": "s3", "text": "最大值 f(1/a)=ln(1/a)-1", "maps_to": "n5", "status": "ok"},
    {"id": "s4", "text": "a≥1/e", "maps_to": "n6", "status": "ok"}
  ]
}
```

对齐算法三步：

1. **符号归一化**：LaTeX → SymPy 表达式；处理 `ln`、`log`、分数、区间。
2. **步骤匹配**：LLM 把用户步骤映射到图节点；规则校验“节点依赖是否满足”。
3. **第一处偏离**：从入口节点向后走，第一个 `missing/partial/wrong` 且其前置节点都 OK 的位置，就是候选断点。

> 注意：不是找“最后错的那一步”，而是找**最早让整条链断掉的认知动作**。后面可能跟着一串连带错误，那些不是根因。

### 4.3 卡点分类：L0–L6

| 层级 | 名称 | 典型信号 | 第一探针 | 不要误判为 |
|---|---|---|---|---|
| **L0** | 读题/语义 | 把“任意”读成“存在”；不知道符号含义 | “把这句话改成自己的话” | 粗心 |
| **L1** | 概念/定理 | 不知道 `f'(x)=0` 是必要不充分；公式记错 | “遮住公式，写出……并解释适用条件” | 基础差 |
| **L2** | 条件转译 | 不会把文字条件变式子；漏参数分类；漏定义域 | “当 a=0 时，这条式子还成立吗？” | 不会做 |
| **L3** | 策略 | 知道所有知识点，但不知道先做什么 | “如果只允许你走一步，你走哪步？为什么？” | 没思路 |
| **L4** | 执行 | 策略对，但算错/丢步骤/符号错 | “这一步再算一遍，只检查符号” | 粗心 |
| **L5** | 校验/元认知 | 不检查边界；信心高但错；不知道哪里不会 | “你觉得自己这题能对几成？为什么？” | 态度问题 |
| **L6** | 资源/状态 | 时间不够、焦虑、注意力 | “先不计时，做第一步” | 学习能力差 |

**判定原则**：

- 至少 2 个独立信号，才允许定层；
- 能落到更具体节点，就不只给 L 层；
- L6 不进入教学内容，只做降难度/休息建议，必要时转介；
- 任何层级都不使用“笨、懒、不认真”等标签。

### 4.4 假设空间：一次只比较 2–3 个可能

系统不追求“全自动诊断”，而是维护一个小假设集：

```json
{
  "session_id": "S_9001",
  "candidates": [
    {"hypothesis": "H_L2_CASE", "label": "漏参数分类", "prior": 0.42, "posterior": 0.42},
    {"hypothesis": "H_L1_DERIV", "label": "导数与极值概念不清", "prior": 0.25, "posterior": 0.25},
    {"hypothesis": "H_L4_CALC", "label": "解不等式计算错误", "prior": 0.18, "posterior": 0.18}
  ]
}
```

先验来自：

- 题目节点的 `common_errors`；
- 用户历史（如果存在）；
- 用户自述“卡在哪”；
- 答案/步骤的初步对齐结果。

### 4.5 探针选择：问“最有区分度”的那个

每个探针都预先标注：它能把哪些假设区分开。

| 探针类型 | 例子 | 主要区分 |
|---|---|---|
| `P_COUNTEREXAMPLE` | “a=-1 时，f(x) 会不会超过 0？” | L2 分类 vs L1 概念 |
| `P_DOMAIN_CHECK` | “x=1/a 在 a<0 时是什么符号？” | L2 条件转译 vs L4 计算 |
| `P_EXPLAIN_STEP` | “为什么 f'(x)=0 能说明是最大值？” | L1 概念 vs L3 策略 |
| `P_NEXT_STEP` | “只允许走一步，你走哪步？” | L3 策略 vs L4 执行 |
| `P_CONFIDENCE` | “这题你能对几成？为什么？” | L5 元认知 |
| `P_RETRIEVAL` | “遮住公式，写出 (ln x)'” | L1/LTS 提取失败 |

选择规则：

1. 只在 top 2–3 假设之间选；
2. 优先选**预期信息增益最大**的探针；
3. 如果两个假设用同一个探针无法区分，换一个；
4. 一轮只问一个；
5. 连续两次“不知道”，降级为二选一/具体数值/半成品填空。

### 4.6 置信度更新与停止条件

用简单的对数几率更新，不做“黑箱打分”：

```text
logit(H_i | e) = logit(H_i) + log LR(e | H_i)
```

每个探针给出一个离散结果（能/不能/不确定/拒绝），对应预设的似然比。示例：

| 探针结果 | 对 H_L2（分类） | 对 H_L1（概念） | 对 H_L4（计算） |
|---|---|---|---|
| 能正确判断 a=0 不成立，但没主动分类 | ×3.0 | ×0.8 | ×1.0 |
| 认为 a<0 时仍有最大值 | ×0.4 | ×2.5 | ×0.6 |
| 计算 `ln(1/a)≤1` 出错 | ×0.8 | ×0.7 | ×4.0 |

**停止条件**（满足任一）：

- 最高后验 ≥0.80，且与第二名差距 ≥0.25；
- 已问 6 轮；
- 用户连续两次说“不知道”，且降级后仍无法判断；
- 用户主动要求“直接告诉我”。

**置信度展示**：

| 后验 | 文案 | 行为 |
|---|---|---|
| ≥0.80 | “我比较确定” | 给卡点卡 + 微干预 |
| 0.55–0.79 | “我倾向于” | 给卡点卡 + 一个验证问题 |
| <0.55 | “目前还不能确定” | 给 2–3 个可能，让用户选/继续问 |

### 4.7 诊断卡：不是“报告”，是“下一动作”

诊断卡固定六块：

1. **卡点**：L 层 + 具体节点（一句话）；
2. **证据**：引用用户的原话/步骤；
3. **排除**：明确说“不是什么”；
4. **置信度**：高/中/低 + 数字；
5. **下一练**：3 分钟能完成的一个动作；
6. **验证**：24 小时/7 天的一道新题。

**反例**（不要这样写）：

> “你的函数与导数基础薄弱，建议加强练习。”

这是标签，不是诊断。它没有证据、没有排除、没有下一步。

### 4.8 失败与降级

| 失败 | 表现 | 降级 |
|---|---|---|
| OCR 错 | 公式识别成别的 | 让用户确认/手改关键符号；保留原图不展示 |
| 解法图缺失 | 新题不在 100 道种子库 | 用 LLM 生成草图 + SymPy 校验；标记“探索模式”，置信度上限 0.65 |
| 多卡点 | 同时缺概念和计算 | 只选“最早断点”，其余记入“后续观察”，不一次讲完 |
| 用户拒绝回答 | 只想要答案 | 解释规则；给“看答案”入口，但退出学习模式，不记录诊断 |
| 用户情绪 | 焦虑/自我否定 | 停止追问，先共情；建议休息/找老师，不做心理判断 |
| 答案泄漏 | 模型想给完整解 | 出口过滤器拦截，重写为提示；记录 `answer_leak` 事件 |

### 4.9 一个最小可用的解法图示例

以 `f(x)=ln x - a x` 为例：

```text
n1 READ      读懂“对任意 x>0，f(x)≤0 恒成立”
n2 CONCEPT   知道要研究 f 的最大值
n3 COMPUTE   求导 f'(x)=1/x-a
n4 CONDITION 分 a≤0 / a>0；确认 a>0 时驻点 x=1/a 在定义域
n5 CONCEPT   a>0 时 f''<0，x=1/a 是最大值
n6 COMPUTE   解 ln(1/a)-1≤0
n7 CHECK     验证 a=1/e 时等号成立；a<1/e 时反例
```

依赖：`n1→n2→n3→n4→n5→n6→n7`。

学生答案对齐后，`n4` 是 `partial`，`n1–n3` 都 OK，`n5–n7` 结果对但建立在未验证前提上。因此根因是 `n4`，不是 `n6`。

**这就是“错哪里了”与“卡在哪”的区别：错在结果，卡在前提。**
