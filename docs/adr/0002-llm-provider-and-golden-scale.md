# ADR-0002: 模型供应商与金标准规模

- **状态**：accepted
- **日期**：2026-10-29
- **决策者**：产品负责人 + 开发（会话内确认）
- **相关**：[ADR-0001](0001-language-and-code-architecture.md)、
  [第 12 章 M2 交付计划](../design/chapters/12-M2交付计划.md)（§12.8 前置未决项）

## 1. 背景

第 12 章把 M2 收窄为「只换措辞」，但 §12.8 与本地 M2 开发说明 §8 都写明：**模型供应商**与**金标准规模**不定，T2 与计划都无法开工。原方案对 golden 有 10 / 100 / 200 三个口径并存，对模型只定了「托管 API、禁止自建 GPU」。

约束来自既有文档，不是新造的：

| 约束 | 出处 |
|---|---|
| 首问 P95 < 8s | 第 12 章 §12.6 |
| 单次成本 ≤ ¥0.8 | 同上 |
| JSON 合法率 ≥ 99% | 同上 |
| 学生作答不出境（合规前置） | `.tmp/m2-digest-main.md` 的脱敏条目 |
| 禁止自建 GPU 推理 | 第 12 章 §12.1 不做清单 |
| LLM 调用只在 `infrastructure/llm/` | ADR-0001 §6.2、`lint-imports` |

## 2. 决策

**采用 DeepSeek `deepseek-chat`，经 OpenAI 兼容协议接入；M2 金标准取 10 条。**

| 项 | 取值 | 理由 |
|---|---|---|
| 供应商 | DeepSeek | 国产托管（学生文本不出境）、中文数学与 JSON 模式稳定、价格量级远低于 ¥0.8/次 |
| 协议 | OpenAI 兼容 `POST /chat/completions` | DeepSeek / Qwen / GLM 同形，**换供应商 = 换 `base_url` + `model`**，不改代码 |
| 抽象位置 | `LLMClient` 端口在 `application/llm.py`；`OpenAICompatibleClient` 在 `infrastructure/llm/client.py` | 守住 ADR-0001 的分层与「LLM 单一咽喉」 |
| 温度/重试 | `temperature=0`，schema 失败重试 1 次，超时不重试 | 非确定性抖动与 8s 预算 |
| 金标准 | 10 条，`eval/golden/golden-v0.1.jsonl` | 通过率 ≥8/10 是最小可判断信号；schema 按 100 条的字段建，扩量不改代码 |

CI 与本地默认 `SYNAPSE_LLM_MODE=off`，走规则版；模型调用只在显式开启且有 key 时发生。回放用 `ReplayLLMClient`（按请求哈希取录制响应），零成本、零抖动。

## 3. 备选与不选的理由

| 备选 | 不选的理由 |
|---|---|
| 阿里 Qwen-Plus | 同为 OpenAI 兼容、可作**一线切换目标**；数学推理略弱，先作为 fallback 候选 |
| 智谱 GLM-4.6 | 同样可切；生态与结构化输出工具链略薄 |
| OpenAI / Claude | 能力上限最高，但学生作答出境需合规确认，且网络延迟对 8s 预算是硬伤 |
| 自建 vLLM + Qwen | 与「禁止自建 GPU」冲突（第 12 章 §12.1） |
| golden 100 / 200 条 | 当前只有 1 道种子题，100 条即同一题 100 份作答；扩题属 M2.5，先做 10 条换取可判信号 |

## 4. 后果

**正面**

- 换模型是一次环境变量变更（`SYNAPSE_LLM_BASE_URL` / `SYNAPSE_LLM_MODEL` / `SYNAPSE_LLM_API_KEY`），无需改代码或发布。
- 单次诊断按 ~2k 输入 / ~0.3k 输出 token 估算，成本在 ¥0.01 量级，¥0.8 上限实际上不会触发；真正的约束是延迟而不是费用（以官网价目为准）。
- 规则版仍是 CI 默认路径，`off` 下全部测试通过 —— 对照基线没有被绕过。

**负面 / 风险**

| 风险 | 缓解 |
|---|---|
| 模型版本漂移导致 golden 抖动 | 记录 `model` 与 `prompt_version`；必要时用 `ReplayLLMClient` 冻结响应 |
| JSON 模式在个别输入下返回非 JSON | Pydantic 校验 + 重试 1 次 + 回退规则实现；合法率进审计 |
| 供应商限流/故障 | 超时即降级，`shadow` 双跑不阻塞返回 |
| 只覆盖 L2 卡点 | 见下节：这是种子图与证据表的边界，不是供应商问题 |

## 5. 已知边界（实测）

10 条 golden 在 `off` 模式下 10/10 通过，但：

- 只有 `H_L2`（参数分类）能越过 `0.80 + 0.25` 的判定线；`EVIDENCE` 只对三个探针有权重，`H_L1` / `H_L4` 最高约 0.65。
- 因此 `no_idea` / `L4` 案例按「低置信不硬判」记为 `expect=stop`，它们验证安全收束，不验证区分能力。
- 平均 2.4 轮就收束，低于第 12 章 §12.6 的 4–6 轮目标；原因是单图证据第 2 轮就饱和，不是追问被削减。

这三条都是 M2.5（学科插件 + 证据标定）的输入，不构成对本次选型的否定。

### 5.1 真实模型实测（2026-10-29，shadow 双跑）

`SYNAPSE_LLM_MODE=shadow` 跑完 10 条 golden，共 24 次模型调用（两次运行，数字取区间）：

| 指标 | 实测 | 门槛 |
|---|---|---|
| JSON 合法率 | 24/24 = 100%（两次一致） | ≥ 99% |
| 单次延迟 p50 / p95 / max | 767–853 / 1101–1161 / 1454 ms | 首问 8s |
| 重试 / 降级 | 0 / 0 | — |
| 10 条通过率 / 平均轮数 | 10/10 / 2.40 | ≥ 8/10 |
| Token（10 条合计） | prompt 5730 / completion 610 | ¥0.8/次 |

两个必须记住的观察：

1. **别名会在服务端解析**：请求 `deepseek-chat`，响应里的 `model` 是 `deepseek-flash`（24/24）。审计记的是实际服务 id，所以要冻结基线，看审计而不是看配置项。
2. **差异率不是质量指标**：24/24 条都“有差异”，但多数只是去标点、口语化（`a=0 时，f'(x)=1/x。它在 x>0 上有零点吗？` → `a=0 时 f'(x)=1/x 在 x>0 上有零点吗？`），少数还丢掉了“对所有 x>0 成立”这个前提。是否真的更好要人工读样本，机器只能判“变了”。

## 6. 改选条件

出现任一情况即回到本 ADR 复议：

1. JSON 合法率连续低于 99%，或重试后仍 < 99%；
2. 首问 P95 > 8s（含重试），且通过降级仍无法收敛；
3. 单价上涨到使单次成本接近 ¥0.8；
4. 合规要求变化（例如必须境内私有化部署）；
5. golden 扩到 100 条后，DeepSeek 与备选模型的通过率差距 > 10 个百分点。

改选时的动作固定为：改 `LLMSettings` 的 `base_url` / `model`，跑 `python scripts/eval/m2_exit.py --live-shadow` 对比，再决定是否切流。
