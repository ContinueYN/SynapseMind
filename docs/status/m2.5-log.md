**S7 NONE 档已落地（2026-10-30，语文）**：`ChinesePlugin`（`subject="chinese"`、`level=NONE`）接进同一个 `SubjectRegistry`，`application/commitment.py` 是唯一开关——STRONG/PARTIAL = 探针 + 卡点卡，NONE = **只出结构提示**。`SessionService.start()` 在建图/对齐之后、探针规划之前分流，语文会话走 `ALIGN → STOP → CLOSED`，`ProbePlanner` 根本不会被调用；**状态机、转移表、对齐器一行未改**。输出是另一张表（`specs/structure-hint.schema.json`，`HintOut`）：`one_line` + 步骤表（`covered`/`missing`）+ `focus_node_id` + `next_step` + 固定 disclaimer，**没有 layer / confidence / next_action / verify**，所以前端渲染不成卡点卡；提示是派生值（每次 `get()` 重建），聚合根不加字段。语文 prompt 为 `graph-v6-chinese`：只要认知动作，明确不要探针与 claim；模型若写了，建图器丢弃并记 `probes_dropped_unsupported` / `claim_dropped_unsupported`，图保留（`review(..., require_probes=False)` 才允许无探针图）。真实 6 道语文题 × 2 段过程（只写前几步 / 写完整）：建会话 12/12、结构提示 12/12、schema 合规 12/12、出卡 0/12、探针 0/12、CLOSED 12/12；同一题两段过程复用同一张图 6/6，覆盖数 full ≥ partial 6/6、focus 后移 4/6；p50 2.3s / p95 3.2s。报告：`eval/reports/m2.5-s7-none-tier.md`。**已知低估**：存在性对齐按节点整句 3-gram 覆盖率判定，语文节点是多分句长句，学生只写前半句仍算 `missing`（partial 均值 1.0/8、full 均值 1.7/8）——方向保守，但覆盖计数偏低；改进候选是分句级匹配或把对齐器做成端口（S8）。

**S8 对齐策略插件化 + 分句级匹配已落地（2026-10-30）**：`SubjectPlugin.aligner_for(problem) -> StepAligner`，`SessionFactory._aligner_for()` 先问插件；`CompositeAligner` 改按 `problem.annotated` 分发（去掉第二套 `annotated_ids`），`api/deps.py` 不再组装它，只留无插件回退。数学标注→`RuleBasedAligner`、生成→`TypeCueAligner`，物理保持 `TypeCueAligner`，语文改用 `ClauseCueAligner`：按 `，；。：、` 切小句（丢弃 <4 字碎片），每句与过程求最长连续公共子串（≥4 字才计），覆盖率 ≥75% 判 `covered`、≥15% 判 `partial`。`AlignmentResult` 加 `partial_node_ids`（默认空），基类两态对齐器永不产生 partial，所以数学/物理结果逐字段不变。`structure-hint.schema.json` 升 **v0.2**，`HintOut.status`/`StructureHint.status` 加 `partial`；提示文案「写到了一部分 / 先把…补全」，前端计数改成「有写到的步数（含部分）」。真实 6 道语文题 × 3 段过程（partial/full/blank）：建会话 **18/18**、结构提示 **18/18**、schema v0.2 **18/18**、服务与直接 `ClauseCueAligner` 一致 **18/18**、出卡/探针 **0/18**、`CLOSED` **18/18**；**同一张图**上旧 full covered 均值 **1.7**，新 full covered **1.7** + partial **2.3**（加权 **2.8**），full≥partial 6/6、新≥旧 6/6、blank 全 missing 6/6。报告：`eval/reports/m2.5-s8-clause-alignment.md`。边界：仍是字面重合，不是语义匹配；`partial` 不是写错；数学/物理没有 opt-in；`domain/dialogue/` 一行未改。

**M2 首问 P95 门禁已通过（2026-10-30 晚，ADR-0004）**：生成图接进主链路后这条指标连续两轮 FAIL（p95 9304 / 11856 ms，预算 8s）。先量再改——真实 key 拆出来四个数：**TTFT 0.8–3.0s**（4 并发不排队）、**prompt 长度不花钱**（37 与 3677 tokens 的 TTFT 无差异）、**输出 ≈220–320 tokens/s**（输出长度就是预算）、`import sympy` **1665 ms** 落在第一次带 claim 的请求里。据此做了五件事：① 生成题的首问不再做装饰性改写（用确定性渲染器，标注种子题仍保留 T3 改写），省掉一次 1.2–4.2s 的模型往返；② prompt 从 `graph-v6` 收紧到 **`graph-v9`**（节点 5–7、探针 4–5、选项恰好 3 个、每个假设在选项上要有正负两向权重），completion 1250 → ≈900 tokens；③ `build_container()` 预热 SymPy，首次带 claim 的请求不再付 1.7s；④ claim 被反例推翻后**只重写区间**（`purpose=graph_claim_repair`，不重生成整图），调用超时取「`SYNAPSE_GRAPH_RETRY_BUDGET_S`（默认 7.5s）− 已用时间」；修复通过记 `claim_repaired`，仍失败/超时/预算不足则保留图、丢 claim、记 `claim_dropped_refuted` + `claim_repair_*`/`retry_skipped_budget`；schema 重试仍无条件（那是拿到图的唯一路径），但**重试 prompt 要求最小可用图（5 节点、3 探针）**，把重试成本压到 ≈3.2s；⑤ 一次模型调用只写一条审计（原来丢弃 claim 的分支写两行，按行统计会把调用数算多）。结果：20 道未见题 **p50 4208/4252 ms、p95 4690/4619 ms**（run5/run7），建会话 20/20，**出卡仍 20/20**（5 探针 98 个、卡点节点 20/20 在图内，建图 p50 4.3s）；物理 6/6、出卡 6/6。**代价**：生成题首问是图里的原始问句（不再润色）；schema 重试那一题拿到的是 5 节点 3 探针的最小图，约占 5% 会话；claim 修复样本 ≈4.5 + 0.8–1.8 ≈ **5.3–6.3s**（受控探针，见下段），20 题里 p95 容得下 2 个。报告：`eval/reports/m2-first-question-run{3,4,5,6,7}.md`、`eval/reports/m2.5-s5-session.md`、`eval/reports/m2.5-s6-physics.md`。

**等式链校验：学生写的等号，机器能判它对不对（2026-10-30 深夜，S5 ⑥）**：存在性对齐只会说「这步没看到」，而学生真正问的是「我错哪了」。新增两个模块：`infrastructure/verification/notation.py` 把 `2x`/`x²`/`sinX`/`根号（16）` 这类中式写法机械转成 SymPy（**读不懂就返回 `None`，绝不猜**），`equalities.py` 把过程里的 `A=B=C` 链拆出来逐对判等号——普通链判两边作为函数是否等价（不等价就举一个具体反例），带 `lim` 的链改判**两边的极限是否相等**（`=1+1` 这种是「极限下相等」，直接判等价会误报）。真实验证：公开问答页里那位学生写的 `=lim[sinX/(X+sinX/cosX)] =lim[sinX/X +cosX] =1+1 =2` 被判「这个等号不成立：x→0 时左边极限 0.5、右边极限 2」——**不需要参考答案**，学生真实错的那一步被机器复算出来。另外 3 条原话是 0 命中：`P_PUB_003` 全程被 CJK 下标挡住（`h台/h锥` 读不懂，跳过），`P_PUB_004` 只有一条链且确实成立（它的错在前提前），`P_PUB_001` 是纯文字。**所以 1/4，且这个 1 是硬 1**。防护纪律：`根号下（80/245）` 若被截成 `80/245`，会把学生**正确**的一步判成错——现在整段跳过记 `notation_unsupported`；`an=3^(n-1)` 这种单侧赋值的「等号」不判，因为它不是断言。`pytest` **327 全绿**（新增 20 条）。边界：只能判「学生自己写出来的等号」，**前提下错**（拿 20 当棱台的高、假设 `an` 是等比）判不了——那需要每一步的参考答案（`node.check`），是下一步。
