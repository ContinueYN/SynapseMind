# SynapseMind 突触智学

> **不是讲这道题，是找到你卡住的那一步。**

学生交来一道题，连同自己的作答过程。系统不评分、不排名、不直接给答案，只用 2–6 轮一次一问的追问，定位他**最早断掉的认知动作**，输出一张带证据的卡点卡：卡点层位、支持它的证据、被排除的竞争假设、后验置信度、下一道该练什么。

这不是一个聊天机器人。**LLM 负责措辞与解题内容，代码决定走向**——它的确定性来自一张 10 状态的显式转移表，而不是提示词里的礼貌请求。

---

## 一、诊断对象：一个可枚举的认知动作空间

卡点不是"这题不会"，而是解题链上第一个断掉的环节。系统把一道题拆成 7 类**认知动作**节点（`READ` / `CONCEPT` / `CONDITION` / `STRATEGY` / `TRANSFORM` / `COMPUTE` / `CHECK`），节点之间是依赖边，构成解法图（DAG）。定位即寻找图中第一个未被正确执行的节点。

| 层位 | 卡点性质 | 典型表现 |
|---|---|---|
| **L0** | 读题 | 漏读条件、误读"任意 / 存在" |
| **L1** | 概念 | 不理解"恒成立"等价于最值 |
| **L2** | 条件转译 | 参数分类缺支、边界情形未检查 |
| **L3** | 策略 | 选错方法，或用未验证的前提 |
| **L4** | 执行 | 变形、求导、解不等式出错 |
| **L5** | 校验 | 不算到底、不检验充分性 |
| **L6** | 元认知 | 自信度与正确率背离 |

**判据是可证伪性**：L2 的卡点必须能给出一个具体反例（令 `a=-1` 时原式不成立），不是模型的看法。

## 二、认知模型：CHC 七维只做探针镜头

解法图每个节点带一个能力需求向量 `demand`，维度取自 CHC（Cattell–Horn–Carroll）能力模型，取值 0–1：

| 维度 | 在单题中的表现 |
|---|---|
| **V** 言语理解 | 读不懂"任意 / 存在""恒成立""至少" |
| **Gf** 流体推理 | 换一个定义或结构就抽不出规则 |
| **Gv** 视觉空间 | 不画图，或画了看不出关系 |
| **WM** 工作记忆 | 多条件同时在线时丢条件 |
| **Gs** 加工速度 | 会做但慢，卡在时间而非方法 |
| **LTS** 长时存取 | 公式想不起来，看到就懂 |
| **M** 元认知 | 信心高但做错，或不知道哪个点不会 |

**这三条是硬约束**：

1. 七维是**假设生成器**，不是诊断结论；
2. 每个维度至少要有 2 个行为信号，才允许进入候选集；
3. **不输出 IQ、百分位、等级**——对外只说"这次卡在哪"，不说"你哪项能力低"。

七维不进入用户视图，只参与一件事：**决定下一个问题问什么。**

## 三、对话内核：显式转移表

10 个状态，事件驱动，转移表写在代码里，不在模型里。

```text
INGEST → PARSE → ALIGN → PROBE ⇄ PROBE
                          ├─→ DIAGNOSE → INTERVENE → VERIFY → CLOSED
                          └─→ STOP → CLOSED
PARSE → NEED_INPUT → PARSE
ALIGN → DIAGNOSE   （仅当断点唯一且证据充分）
ALIGN → STOP       （超纲 / 无法建图）
```

### 硬约束

| # | 约束 | 实现层 |
|---|---|---|
| 1 | 一次一问：`question` 只允许一个问号，选项 ≤ 4 | Schema 校验 |
| 2 | 前 3 轮不出现最终答案；`solution` 字段在类型上不存在 | 类型系统 |
| 3 | **LLM 不决定状态**：只输出动作候选，状态由守卫推进 | 转移表 |
| 4 | 低置信不硬判：`posterior < 0.55` → 继续问或收束 | 阈值守卫 |
| 5 | 轮次上限 6：到顶必须收束为"可能卡点 + 缺什么证据" | 计数器 |
| 6 | 进入诊断需 `posterior ≥ 0.80` **且** `margin ≥ 0.25` | 后验 + 边际 |
| 7 | 动作白名单：`ask` / `hint` / `confirm` / `diagnose` / `intervene` / `stop` / `offer_answer_exit` | 枚举 |
| 8 | 每轮回答写入证据链，缺失证据不得进入诊断 | 证据门禁 |

后验用 log-odds 累加，softmax 归一；答案选项的似然权重是领域常量，不由模型生成。

## 四、答案单向阀

学习模式下，最终答案**在物理上不可达**：答案存储与提示装配是两个不同的对象，中间隔着五层。

| 层 | 闸门 |
|---|---|
| 检索 | `chunk_type != solution` 硬过滤 |
| Prompt | 系统提示禁止给出最终答案与完整步骤 |
| Schema | 输出结构不含 `solution`；`question` 长度与问号数校验 |
| 出口 | 禁用词表 + 字符级 5-gram 重叠检测；命中即替换为安全追问 |
| 回归 | 红队用例集；泄漏率必须为 0 才发布 |

出口层是装饰器，不依赖模型自省：`AnswerLeakGuard` 与任何 composer 解耦，可独立单测。**模型没有第二次机会**——命中即改写。

另有显式出口：用户可主动退出学习模式并获得答案，但该次会话不生成卡点卡、不计入诊断。

## 五、证据链与检索

诊断结论必须可回溯到三类证据：对齐证据（步骤偏离）、探针证据（回答支持的假设）、检索证据（知识卡引用）。

检索管线（`RAG`）：

```text
Query 理解 → 改写（条件触发）→ 混合召回 → RRF(k=60) → rerank 50→8 → 阈值过滤 → 上下文组装
                │
                ├─ dense：pgvector HNSW（halfvec_cosine_ops, m=16, ef_construction=200）
                └─ sparse：PostgreSQL tsvector + 学科词典
```

- 融合用 **RRF**，不用加权求和——余弦与 BM25 的量纲不可比；
- `score < 0.35` 丢弃；通过条数 < 2 时转"证据不足"分支，**不生成确定性结论**；
- 检索必须带租户与可见性过滤，过滤发生在召回之前。

## 六、技术架构

```text
Browser
  │
Nginx（SSE 关闭缓冲、限流、超时）
  ├─ web    Next.js：RSC / ISR / JSON-LD / SSE 外壳
  └─ api    FastAPI：状态机 / 诊断 / 证据 / 防护
        ├─ worker   Arq：OCR 后处理 / 知识 ETL / 离线评测 / 红队
        ├─ PostgreSQL 16 + pgvector   业务数据 + 知识卡 + 向量索引
        ├─ Redis 7                    会话 / 幂等 / 限流 / SSE 重放
        └─ 对象存储                    题目原图，7 天生命周期
```

**分层边界由 CI 强制**：`domain` 不认识数据库与模型 SDK，`application` 只依赖端口（Protocol），`infrastructure` 提供适配器。跨层 import 直接导致流水线失败。

| 关注点 | 决策 |
|---|---|
| 状态机 | 显式转移表，不用图引擎——可单测、可回放、可静态审查 |
| LLM 接入 | 只落在 `infrastructure/llm`；受控结构化输出 + 重试 + 降级 |
| 解法图来源 | 学科插件提供；可手写也可生成，生成物必须过同一份 `solution-graph.schema.json`，否则显式失败、不生成卡点卡 |
| 诊断证据 | 种子题用人工标定的 log-odds 表；生成图由模型为每个选项给出权重，结构规则强制覆盖与正负对比，未知图不借用别题的权重 |
| 异步任务 | 只跑离线活；**LLM 主链路绝不进队列**——进队列就破首问预算 |
| 迁移 | Alembic 向前兼容，不做自动 down migration |
| 可观测 | OpenTelemetry 全链路 trace + Prometheus/Grafana；首问 P95 与 JSON 合法率进大盘 |
| 灰度 | 镜像 tag + 按会话哈希分流；回滚为一次环境变量变更 |

## 七、评测

**评测是产品的一部分，不是上线前的仪式。** 判据只有一条：能不能证明"说得准"。

| 指标 | 门槛 |
|---|---|
| 与双教师卡点一致率 | ≥ 75% |
| "说中了"（用户主观确认） | ≥ 70% |
| 答案泄漏率 | = 0 |
| 追问 JSON 合法率 | ≥ 99% |
| 检索 recall@8 | ≥ 0.80 |
| 首问 P95 | < 8s |

- 金标准集按能力分桶（检索 / 归因 / 处方 / 引用 / 安全），双人标注，一致性 κ ≥ 0.75；
- 红队集覆盖诱导、越狱、多轮套答案；
- 状态机回放必须与金标准轨迹一致——这是"可回放"的实际含义，不是修辞；
- 生死线：50 次诊断一致率 < 60%，停止扩张。

## 八、架构决策

被否决的方案与理由，比采纳的方案更能说明系统边界。

| 否决 | 理由 | 代价 |
|---|---|---|
| LangGraph 式图引擎 | 可单测、可回放、可静态审查 | 新分支要写代码，不能靠改配置变出来 |
| 自由编排的多 Agent | 一次一问、6 轮上限、低置信不硬判，必须是**禁止**而非**请求** | 放弃灵活性与话题热度 |
| 提前引入外部检索引擎 | `tsvector` + `pgvector` 在题库量级足够，等真实检索压力出现再评估 | 放弃"分布式"标签 |
| MySQL / Spring Cloud 拼企业味 | 少一层分布式事务，多一层可验证性 | 放弃部分技能清单落点，取舍记录在 ADR |

完整选型与改选条件见 [ADR-0001](docs/adr/0001-language-and-code-architecture.md)。
